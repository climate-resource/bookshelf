Confines the SDK retry policy to requests that are safe to replay, so a transient 5xx can no longer duplicate a write.

- Only idempotent methods (`GET`, `HEAD`, `OPTIONS`, `TRACE`, `PUT`, `DELETE`) are retried on a 5xx.
  A `POST` or a `PATCH` now surfaces the error to the caller, because none of the write endpoints accept an idempotency key.
- A network failure on a write is only retried when the connection never came up, which is the one case where no bytes reached the server.
- `501` and `505` are no longer retried on any method, because they describe a permanent property of the server.
