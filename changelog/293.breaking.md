Made `bookshelf record` stricter about what a build is given and how it ends.

- `-p` and `run_record(parameters=...)` now refuse a key that is not a plain identifier, a dunder name, or a name with no top-level `name = value` assignment in the build file. These used to be accepted and silently changed nothing. The refusal is `RecordRefusedError`, which is also a `ValueError`, and the CLI exits 2.
- A build that calls `sys.exit`, even `sys.exit(0)` to stop early, now fails the record.
- `code_ref` and its `+dirty` marker now describe the clone as it was before the build ran, rather than when the build opened its activity.
