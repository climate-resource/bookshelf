Stores credentials in the `0600` credentials file rather than the OS keychain.
macOS binds a keychain item's access control list to the code signature of the process that reads it,
and an SDK installed from PyPI runs under an ad-hoc signed interpreter whose hash moves on every upgrade,
so the unlock prompt returned on every command and `always allow` could not silence it.
Anyone already logged in has to run `bookshelf auth login` again to move their secret,
and `bookshelf auth list` names any deployment still waiting for that.
Set `BOOKSHELF_USE_KEYCHAIN=1` to keep using the keychain,
which is worth doing where the interpreter is properly signed
or where the backend is a real secret service.
