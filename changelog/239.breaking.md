Removed the opt-in OS keychain credential store, so `$BOOKSHELF_USE_KEYCHAIN` no longer does anything.
Credentials live in the `0600` credentials file, which has been the default for several releases.
Run `bookshelf auth login` again if an earlier run left a secret in the keychain.
This also drops `keyring` as a dependency.

Moved `--api-url` onto the `bookshelf` command itself, ahead of the subcommand.
Run `bookshelf --api-url URL publish bundle` where it used to be
`bookshelf publish bundle --api-url URL`.
The old position is now a usage error naming the option, so a stale call fails
rather than quietly reaching the default deployment.
`$BOOKSHELF_URL` is unaffected.

Rendered the CLI's human output from the same document `--json` emits, through one renderer.
Labels now come from the payload keys, so `bookshelf show` reports `License` where it said `Licence`,
and `bookshelf upload` reports `Outcome aliased` where it said "already held, nothing new was made".
`--json` is unchanged, so every automated caller keeps the output it had.
