`used=` now records an input the recipe names by `bookshelf://sha256/<hex>`,
so a book built from an uploaded file carries the lineage back to that file.
An uploaded input belongs to no book and the bundle records nothing for it,
so the manifest cites it under the new `used_digests` field rather than by a name it does not have,
and replay resolves that digest against what the publishing organisation holds.

- Manifest schema 3.3 adds `used_digests` to a resource record.
  The field is additive, so an older reader still loads the bundle and drops the lineage it cannot model.
- Publishing needs a deployment carrying `content_hash` in a replay `used` reference,
  which is bookshelf-platform 642.
- An input reached through a book coordinate still cannot be cited.
  Replay resolves a digest against the publishing organisation alone,
  and a referenced book may belong to another one.
