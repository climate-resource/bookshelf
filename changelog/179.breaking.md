Replaced the flat recipe with `volume:`, `build:` and `versions:` sections,
and made `bookshelf record --version` required.

- A recipe declares the volume once, the build once, and each version explicitly.
- Unknown keys are rejected at every level, rather than silently ignored.
- `collection`, `authors` and `notebook` moved under `volume:` and `build:`.
  The flat form no longer loads, and a recipe using it is rejected with a message naming the new shape.
- Every version states its own `license`, and there is no volume-level default.
  A `license` under `volume:` is rejected with a message saying to move it onto each version.
- Every version states its own `visibility`, and omitting it means `hidden`.
  This lets one version be embargoed while the rest stay public.
  A `visibility` under `build:` is rejected with a message saying to move it onto each version.
- The inputs a version is built from are declared under `resources:`,
  and each states a `type` from the same set the platform registers a resource under.
  An unknown type is rejected when the recipe loads, naming the ones that are allowed.
- `--version` selects the version to record, and it is the only place a version is stated.
  A build file calls `bookshelf.setup()` without a version, and `-p` is unchanged.
