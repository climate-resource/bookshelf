Changes two behaviours a caller can observe:

- Serialising a `DataFrame` without the `dataframes` extra now raises `DataFrameSupportError` rather than `ImportError`.
  The consume side already reported a missing extra this way,
  so the same situation raised two different types depending on which side of the SDK the caller was on.
  `DataFrameSupportError` subclasses `BookshelfError`, so code catching `BookshelfError` needs no change.
  Code catching `ImportError` around a produce call needs updating.
- The SDK and the CLI now share one version ordering, so they agree on which book is the newest.
  `Bookshelf.list_books()` split a version on `.`, `_` and `-`,
  which read a prerelease as an extra trailing segment and made `1.0.0-rc1` sort as newer than `1.0.0`.
  The CLI read the same label as SemVer and sorted it as older.
  Over a sample of eleven realistic version labels the two disagreed on 14 of the 55 pairs.
  The SemVer reading now applies to both, from a single `version_key` in `bookshelf._core.names`:
  a prerelease sorts before the release it leads to,
  build metadata after `+` is not part of the order,
  trailing zero components do not make a version newer,
  and comparison is case insensitive.
  This changes the order `list_books()` returns for volumes that publish prerelease versions.
  A volume whose versions are plain numbers is unaffected.
  A version is the upstream data version and is not obliged to be SemVer,
  so a label that does not parse still falls back to its own text
  and keeps sorting deterministically rather than raising.
