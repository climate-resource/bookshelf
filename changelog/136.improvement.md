Makes `OAuthError` a `BookshelfError`, so one `except BookshelfError` around a login catches every flow failure.

The browser and device-code flows raised a bare `Exception` subclass.
A caller therefore had to catch two unrelated trees to cover a single login,
and an `OAuthError` escaping a command bypassed the CLI's exit-code table.

`OAuthError` describes the flow rather than one HTTP response,
so it carries no status code and stays outside the `APIError` tree.
A token endpoint answering with an `{"error": ...}` body still raises `OAuthProtocolError`.

Restores the coverage signal to CI, which the SDK adoption had dropped.

The SDK test job lost `--cov` when it moved onto a job of its own,
and the `coverage xml` and Codecov upload steps left attached to the producer job when that was retired.
Neither change set out to alter coverage policy,
so the repository kept a `fail_under` gate that nothing ran.

Coverage is now measured over `packages/bookshelf/src` rather than over `packages`,
so the figure describes the library and not the tests that exercise it.
The root and package configurations state the same source, the same exclusions and the same gate,
so a run started from either directory reports the same number.
`fail_under` is 80, which sits just under the measured floor.
