Changes two behaviours a caller can observe:

- Serialising a `DataFrame` without the `dataframes` extra raises `DataFrameSupportError`
  rather than `ImportError`.
  Code catching `ImportError` around a produce call needs updating.
- The SDK and the CLI now share one SemVer version ordering, so they agree on which book is the newest.
  This changes the order `list_books()` returns for volumes that publish prerelease versions.

Follows the platform's one discovery contract,
which removes every duplicate mechanism for a descriptive fact:

- Removes `abstract` from the recipe's `defaults:` section.
  A dataset summary is `description`,
  which is the name the platform carries and the one producers already use.
- Sends `description` and `authors` inside the book's `discovery` object rather than beside it,
  matching where the platform now carries them.
- States the licence on every book the recipe resolves.
  The platform no longer defaults a draft's licence from its volume, so the producer resolves it,
  which is what the recipe's `defaults:` section was always for.

Replaces the five-call publish sequence with the platform's one replay endpoint,
`POST /v1/bundles/replay`:

- Uploads the managed bytes,
  then sends the whole bundle in one transactional request that registers the resources,
  mints the recorded activity's provenance edges,
  drafts the book, attaches every entry and publishes it.
  A failure anywhere rolls all of it back.
- Derives a recorded activity's id from its kind, code ref, config hash and parameters,
  rather than minting a fresh one per run.
  Recording the same build twice now writes the same manifest,
  and the runner is left out so the same build on a laptop and on CI is the same activity.
- Adds `Bookshelf.replay_bundle` and its asynchronous counterpart,
  so the publisher drives the replay through the facade rather than through its transport.
- Addresses every resource by its bundle-local name, which the platform maps to a tracking id itself.
  A resource therefore needs a name when it is registered,
  and it keeps that name inside the book it is attached to.
- Records `used` lineage as the names of resources the same bundle carries,
  each recorded before whatever consumes it.
  Citing a resource the bundle does not carry now fails while the bundle is recorded,
  and `Bundle.validate` refuses a manifest whose lineage does not resolve in order.
  A published resource reached through a `bookshelf://` reference is one of those,
  so a feedstock built on another book cannot yet state that lineage.
  That loss is unintended and tracked by an xfail rather than accepted.
- Moves the seal to the server, which computes it from the request alone.
  `compute_book_bundle_hash`, `draft_bundle_book` and `draft_bundle_book_sync` are gone,
  and so is the `bundle_hash` field on `bookshelf validate` and `bookshelf publish`.
- Returns a `BundleReplayResponse` from `replay_bundle` and `replay_bundle_sync`
  rather than a draft book.
  `PublishOutcome` reports `converged`, `resource_count` and `dedupe_hits`,
  and reports `no-op` only for a converged replay that also wrote nothing.
  `bookshelf publish --dry-run` sends nothing at all because convergence is no longer a probe.
- Raises the bundle manifest to schema 3.0, which keys its resources by name.
  A bundle recorded under an older schema is refused with `InvalidBundleError` rather than migrated,
  because the names it would need were never recorded.
  Re-record it with `bookshelf record`.
